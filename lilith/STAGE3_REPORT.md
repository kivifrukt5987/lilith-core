## 1. Что сделано

| Блок | Файлы | Суть |
|---|---|---|
| **Журнал** | `memory/journal.py` | aiosqlite: таблицы `messages` / `facts` / `meta`, изоляция по `agent_id`, кольцевой лимит `journal_max_messages`, метка `summarized_upto` для границы саммаризации. Один connection + lock, данные переживают перезапуск |

| **Рантайм-настройки** | `memory/runtime.py` | `summarize_every_n`, `top_k`, `rag_enabled`, `auto_summarize` меняются из программы: шестерёнка «⚙ память» в панели или `POST /api/memory/settings`; значения сохраняются в `data/runtime_settings.json` и применяются при старте поверх YAML |
| **Оркестратор** | `memory/__init__.py` | `MemoryCore`: старт/стоп, `retrieve()` (воспоминания в контекст), `remember_turn()` (журнал + RAG + саммаризатор), `describe()` для healthz/панели |
| **Шина** | `app.py`, `brain/chat.py` | Перед ответом — `retrieve()` и второе system-сообщение «ВОСПОМНИНАНИЯ…»; после ответа — `remember_turn()`; если создано саммари — системный кадр «📜 память: создано саммари последних N сообщений» **после** финального кадра |
| **HTTP** | `app.py` | `GET/POST /api/memory/settings`, `GET /api/memory/state`, блок `memory` в `/healthz` |
| **Панель** | `webui/index.html` |Drawer «📜 ПАМЯТЬ · НАСТРОЙКИ»: порог саммари, top_k, тумблеры авто-саммаризации и RAG, сохранение в один клик |
| **CLI** | `run.py` | `--with-memory` (включает память без правки конфига) |

## 2. Как запустить локально

```bat
:: демо памяти без модели
python -m lilith_core.run --mock-brain --with-memory

:: боевой режим: brain_enabled + memory_enabled в config.yaml (или флаги)
python -m lilith_core.run
```

Настройки памяти из программы: шестерёнка «⚙ память» в шапке панели
(порог саммари, top_k, тумблеры) или `POST /api/memory/settings`
(`{"summarize_every_n": 25}` и т.п.). Сохраняется в `data/runtime_settings.json`,
переживает перезапуск. YAML править не нужно.

Диагностика: `GET /api/memory/state` (журнал, RAG, саммаризатор, рантайм-поля),
блок `memory` в `/healthz`, строки «Саммари готово…» в `logs\lilith.log`.

## 4. Ограничения этапа 3

* Эмбеддер по умолчанию — HashEmbedder (отпечатки близости, не семантика).
  Качество поиска вырастет с `embedding_model: sentence-transformers/…` (CPU, ставится
  экстрой `[memory]`) — точка переключения одна, в конфиге.
* Воспоминания подмешиваются вторым system-сообщением; ранжирования по важности пока нет.
* Саммари склеиваются по порядку сообщений, без тематической кластеризации.

## 5. Готовность к этапу 4 («Уши и горло»)

Память не блокирует голос: `MemoryCore.retrieve/remember_turn` вызываются из шины,
голосовой слой будет тем же источником реплик. Профиль `summarizer` уже умеет думать
дешёвой моделью — для голоса это пример того, как держать разные профили горячими.

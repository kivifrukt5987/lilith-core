## 1. Причина (шесть независимых, все по факту донесения)

### 1.1 Фон чёрный, хотя режим `Dwm` применился

В Player.log билда было `прозрачность окна: Dwm (hwnd=…)` — значит `GetActiveWindow()` сработал,
`DwmExtendFrameIntoClientArea` вызван, стили проставлены. И всё равно фон чёрный непрозрачный.

Причина **не в Win32-коде**, а в презентации кадра: Unity 6 по умолчанию отдаёт кадр через
**flip model swapchain**, а при flip-модели альфа-канал до DWM не доезжает — композитор
получает непрозрачный кадр и честно рисует его чёрным. Рецепт прозрачного окна в Unity 6
(проверенный сообществом, Unity Code Monkey «How to Make a Transparent Unity App», Unity 6):
камера black/alpha 0 + `DwmExtendFrameIntoClientArea(-1)` + **Fullscreen Mode = Fullscreen
Window** + **Use Flip Model Swapchain = ❌**. Первые два пункта у нас были, последние два —
настройки плеера, их из кода не поставить.

Вывод: «чини Dwm-путь» в коде не чинится. Чинится **одним чекбоксом** в Player Settings,
а код обязан (а) сам выставить то, что может, и (б) **написать эту подсказку в Player.log**,
чтобы чёрный фон объяснял себя сам, а не отправлял нас в следующий замер.

### 1.2 `Layered Color Key`: окно металось и рябило

Гипотеза архитектора («цикл `SetWindowPos`/`SetLayeredWindowAttributes` каждый кадр»)
в `Update()` не подтвердилась — там были только F8/F9 по нажатию. Но Win32-вызовы
повторялись по другому поводу: `ApplyWindowSize()` и `DockBottomRight()` зовутся из клиента
на кадр `persona` (и на каждый reconnect), и каждый вызов делал `SetWindowPos` **без сравнения
с текущим прямоугольником**. Плюс `Apply()` дважды проставлял `GWL_STYLE` подряд.
Рябь добавлял MSAA: он размывает альфу и края, а у цветового ключа края и есть рабочий
инструмент — отсюда «кайма антиалиасинга» (пункт 6 донесения).

### 1.3 Три полевые правки = класс ошибок player-only веток

| Правка Кирюши | Ошибка | Почему её не было видно |
|---|---|---|
| `LilithFaceClient.cs:322` — скобки вокруг тернарника в интерполяции | **CS8361** | синтаксически код валиден: парсер видит `interpolation` → `conditional_expression` и молчит |
| `TransparentWindow.cs:234/259` — `rect.Left` → `rect.left` | **CS1061** | ветка `#if UNITY_STANDALONE_WIN && !UNITY_EDITOR` в Editor вырезана, а типов чекер не знает |
| `make_test_vrm.py` — `commercialUsage: "personal"` → `"personalNonProfit"` | невалидный enum VRM 1.0 | `validate()` проверял структуру и геометрию, но не значения enum'ов |

Общее: **player-only `#if`-ветки проверяются только сборкой F7.** Это теперь правило в
`HANDOVER.md`, а что можно автоматизировать — автоматизировано (§2.6).

### 1.4 `commercialUsage: "personal"` — значения нет в спецификации

Сверено по `vrm-c/vrm-specification`, `specification/VRMC_vrm-1.0/meta.md`: допустимы
`personalNonProfit` / `personalProfit` / `corporation` (дефолт — `personalNonProfit`).
Наш генератор с 0.6.0 писал `"personal"`. Правка Кирюши верна; теперь она закреплена
таблицей enum'ов и гвардом с контрольным выстрелом.

### 1.5 Оверлей в билде быстро мигает

`OnGUI` вызывается несколько раз за кадр (Layout/Repaint/…), а значения (`Audio.BufferedMs`,
визема, счётчики) между вызовами меняются — глаз читает это как дрожание строки. В Editor
реже, потому что там меньше событий и другой темп.

### 1.6 Окно не закрыть пользователю

Без рамок нет крестика, а `WS_EX_TOOLWINDOW` убирает окно из Alt+Tab и таскбара. Единственный
способ выйти — диспетчер задач. Так жить нельзя.

## 2. Что сделано

### 2.1 Прозрачность в билде (пункт 1 донесения)

| Что | Где | Эффект |
|---|---|---|
| `QualitySettings.antiAliasing = 0` в `Apply()` | код | MSAA больше не размывает альфу — лечит и чёрную кайму на цветовом ключе (пункт 6) |
| `PrepareCamera()` вызывается из `Apply()` | код | SolidColor + альфа 0 гарантированы даже если в сцене камеру подправили |
| `LogModeHints(mode)` | код | при режиме `Dwm` в Player.log пишется **точная подсказка**: Fullscreen Window + `Use Flip Model Swapchain = ❌` |
| `DwmExtendFrameIntoClientArea` возвращает `hr` в лог | код | `hr=0x00000000 (0 = успех)` — видно, реально ли применилось стекло |
| `SetLayeredWindowAttributes(..., 255, LWA_COLORKEY)` возвращает `ok` в лог + сам ключ `#FF00FF` | код | видно, принял ли Win32 цветовой ключ |
| **F7 — смена режима живьём** (`CycleMode()`) | код | A/B всех режимов **в одной сборке**, без ребилда; каждая смена логируется |
| Режим `Off` получил честный тёмный непрозрачный фон | код | раньше при `Off` камера оставалась с альфой 0 и окно выглядело чёрной дырой — цикл F7 читался бы как поломка |
| Раздел **§4.5 Player Settings** | `SCENE.md` | таблица обязательных настроек плеера + Always Included Shaders + сплэш |
| Строка режима сохранена | код | `прозрачность окна: Dwm (hwnd=…) · toolWindow=True · frame=False · хоткей закрытия Ctrl+Alt+Q · F7 смена режима · F8 вкл/выкл · F9 в угол` |

Режим `Dwm` остался **дефолтом**: по рецепту Unity 6 он даёт настоящую per-pixel альфу
(без цветового ключа и без каймы). `LayeredColorKey` — запасной, `Off` — для отладки.

### 2.2 Win32-дисциплина (лечение «металось и рябило», пункт 1.2)

`Apply()` разделён на три метода, каждый делает одно:

* `ApplyStyles(mode)` — стили и расширенные стили. Сбрасывает `WS_EX_TOOLWINDOW |
  WS_EX_APPWINDOW | WS_EX_LAYERED` **перед** установкой, поэтому режимы не залипают.
* `ApplyTransparency(mode)` — `DwmExtendFrameIntoClientArea` **или**
  `SetLayeredWindowAttributes`, ровно один вызов на смену режима + один `SetWindowPos`
  с `SWP_FRAMECHANGED`.
* `Reposition(force)` — считает целевой прямоугольник и **не вызывает `SetWindowPos`
  вовсе**, если он равен текущему. `ApplyWindowSize()` и `DockBottomRight()` теперь
  просто зовут `Reposition`.

Гвард: в `Update()` нет ни одного Win32-вызова (проверяется по списку из пяти функций),
`SetLayeredWindowAttributes` встречается в файле **ровно один раз**.

### 2.3 Окно-инструмент и выход (пункты 2 и 4 донесения)

| Поле конфига | Дефолт | Что делает |
|---|---|---|
| `windowToolWindow` | ✅ | ✅ → `WS_EX_TOOLWINDOW`: окна нет в Alt+Tab и таскбаре. ❌ → `WS_EX_APPWINDOW`: переключается как обычное приложение |
| `showWindowFrame` | ❌ | ✅ → возвращает `WS_CAPTION | WS_THICKFRAME | WS_MINIMIZEBOX | WS_MAXIMIZEBOX` (крестик и рамка; прозрачность при этом не работает) |
| `closeHotkeyEnabled` | ✅ | разрешить закрытие хоткеем |
| `closeHotkey` | `Q` | клавиша; срабатывает **только вместе с Ctrl+Alt** (оба модификатора проверяются с обеих сторон клавиатуры) |

Хоткеи в билде: **Ctrl+Alt+Q** — выход, **F7** — смена режима прозрачности,
**F8** — вкл/выкл прозрачность, **F9** — в правый нижний угол.

### 2.4 Оверлей без дрожания (пункт 3 донесения)

Строка оверлея собирается один раз за кадр в `Update()` → `BuildOverlayText()` → поле
`_overlayText`; `OnGUI()` рисует **только снимок** и **только на `EventType.Repaint`**.
Гвард проверяет, что в `OnGUI` не вернулись вычисления (`Describe()` там запрещён).

### 2.5 Мета VRM по спецификации (хвост очереди)

* `META_ENUMS` — таблица допустимых значений четырёх enum-полей по `meta.md` VRM 1.0.
* `META_BOOLEANS` — пять булевых полей.
* `validate_meta()` — поднимает `ValueError` на: пустых обязательных `name` / `authors` /

* Генератор пишет `commercialUsage: personalNonProfit`, `creditNotation: required`,
  `allowRedistribution: false`, `modification: prohibited`.
* Куб пересобран: **21 572 Б** (было 21 480 Б — добавились три поля меты),

### 2.6 Инструмент: правило CS8361 в чекере (важнее самой правки)

`scripts/check_csharp_syntax.py`:

* новое правило `find_interpolation_misuse()` — обходит узлы `interpolation` и краснеет,
  если прямой потомок `conditional_expression` (а не `parenthesized_expression`);
* правило подключено в `check_file()` **в обе ветки** (`--define`), рядом с CS4032;
* `build_parser()` вынесен из `main()`, чтобы тесты гоняли правило по отдельным файлам;
* **контрольный выстрел №1** (синтетика): правило нашло `broken_interpolation.cs:5:26`;
* **контрольный выстрел №2** (реальный код до правки): правило нашло ровно
  **`LilithFaceClient.cs:322:45`** — ту самую строку, которую Кирюша правил в поле.

После правки: `Файлов: 11, веток: 2, ошибок: 0`.

Второй, **независимый** сканер (без tree-sitter, brace-matching по `$"…"`) живёт в
`tests/test_hotfix_066.py::interpolation_holes` — две реализации одного правила ловят
друг друга. Он же отличает тернарник от `?.` и `??` (контрольный выстрел №3).

Гвард RECT: объявленные поля структуры сверяются со **всеми** обращениями `rect.<member>`
в обеих ветках — то есть CS1061 на этом типе ловится без компилятора.

### 2.7 Silero TTS (хвост очереди)

В `packs.yaml` **не** добавлен: пак — это файл весов со стабильным URL и sha256, а Silero
ставится пакетом PyPI и тянет веса через torch.hub. Выдумывать `ref`/`sha256` не буду
(урок D5.4). Вместо этого:

* `pyproject.toml`, extras `[voice]` += `silero>=0.5`. Проверено по PyPI: официальный
  пакет — **`silero`** 0.5.5 (Silero Team, `github.com/snakers4/silero-models`, тянет
  `torch>=1.12`, `omegaconf>=2.1`, `numpy>=1.23`). **`silero-tts`** на PyPI — чужая
  обёртка версии 0.0.5, не она.
* **Лицензия моделей Silero — CC BY-NC 4.0.** Записана комментарием в `pyproject.toml`
  и в `models/packs.yaml`: для домашнего проекта нормально, для коммерции — нет.
* До установки пакета голосовой путь отдаёт mock-чанк («прык») — это норма (ADR-022).

### 2.9 Сплэш Unity (пункт 5 донесения) — вердикт: норма, не чиним

Сплэш — лицензионное окно плеера, оно создаётся **до** первой сцены и закрывается само;
наш квадрат появляется после, потому что наш код живёт в `Start()` первой сцены.
Отключается в Player Settings → Splash Image → **Show Splash Screen ❌**, но только на
Unity Plus/Pro; на Unity Personal его требует лицензия. В код не лезем — записали в
`SCENE.md` §4.5 и в troubleshooting `README.md`.

## 3. Карта приборов замера Д (что читать в Player.log)

| Строка в Player.log | Что значит |
|---|---|
| `прозрачность окна: Dwm (hwnd=…) · toolWindow=True · frame=False · хоткей…` | окно настроено; режим и флаги — фактические |
| `DwmExtendFrameIntoClientArea: hr=0x00000000 (0 = успех)` | Win32 принял стекло. `hr != 0` → DWM недоступен/выключен |
| `[Lilith] DWM-стекло в Unity 6 работает только при двух настройках плеера: …` | подсказка; если фон чёрный — сначала сюда |
| `SetLayeredWindowAttributes: ключ #FF00FF · ok=True` | цветовой ключ принят (режим `LayeredColorKey`) |
| `[Lilith] F7: режим прозрачности Dwm → LayeredColorKey` | смена режима живьём, без ребилда |
| `[Lilith] хоткей закрытия (Ctrl+Alt+Q) — выходим` | окно закрыто штатно |
| `рукопожатие: h0…h9` + канарейка `главный поток ЖИВ` | приборы 0.6.5 на месте, регрессии нет |

**Если фон всё ещё чёрный при `hr=0x00000000`** — значит flip-model swapchain всё ещё
включён (или Fullscreen Mode = Exclusive). Это единственная оставшаяся гипотеза, и она
проверяется одним чекбоксом, а не новым замером.

## 7. Чего я НЕ делала — и почему

1. **Per-pixel альфа через `UpdateLayeredWindow`.** Она требует, чтобы поверхность окна
   рисовали мы (32-битный ARGB DIB), а её рисует swap chain Unity — два владельца одной
   поверхности. Это ~250 строк P/Invoke, которые в песочнице не проверяются вовсе, ради
   эффекта, который даёт рецепт §5.2. Если F7 покажет, что DWM не работает **ни с какими**
   настройками плеера, — вернёмся, но как к этапу (отдельное layered-окно), а не к хотфиксу.
2. **Не выдумывала `ref`/`sha256` для Silero.** Урок D5.4: манифест без проверяемого
   источника хуже отсутствия манифеста.
3. **Не чинила сплэш Unity.** Это лицензионное окно плеера, а не наш код (§2.9).
4. **`MToon10` в Always Included Shaders не добавляла** — процедурному кубику MToon не
   нужен, а лишние шейдеры в билде стоят памяти и времени сборки. Вернёмся, когда приедет
   настоящая VRoid-модель: строка уже стоит в таблице `SCENE.md` §4.5.
5. **Проверено только F7** (честный список того, что песочница доказать не может):
   реальное поведение DWM на Win10 19045, эффект `Use Flip Model Swapchain`, видимость
   окна в Alt+Tab/таскбаре, работа `Application.Quit()` по хоткею, отсутствие ряби.
   Всё это — строки Player.log из §3; если хоть одна не появится, виноват мой код, а не
   машина.

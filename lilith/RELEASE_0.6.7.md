## 1. Причина

### 1.1 Пожелание архитектора (6 пунктов, дословно по сути)

Окно — инструмент — стало гвоздём в правом нижнем углу. Для игр и RP нужно:

1. **Драг** за любую точку окна, пока держишь Ctrl+Alt (`WM_NCHITTEST` → `HTCAPTION`);
   без модификаторов клики работают штатно;
2. **Ctrl+Alt+стрелки** — пошаговое смещение (конфиг `windowMoveStep`, дефолт 32 px);
3. **F10** — цикл углов дока BR → BL → TR → TL; **F9 прежний** = правый нижний;
4. **Персист** ручной позиции в `data/window_state.json`, приоритет над
   `dockBottomRight` до первого нажатия F9/F10;
5. **Глобальные хоткеи** `RegisterHotKey` — Ctrl+Alt+Q без фокуса: Unity Input слушает
   только фокус, из игры окно было не закрыть;
6. **КРИТИЧНО**: F11 — click-through (`WS_EX_TRANSPARENT`), клики проходят СКВОЗЬ окно
   в игру. **ТОЛЬКО в связке с п.5**, иначе окно станет неубиваемым призраком.

### 1.2 Шесть багов в моём собственном новом коде — пойманы гвардами до сборки

Причина моя: первую редакцию пакета я написала быстрее, чем гварды к ней. Писала гварды —
гварды и поймали. Ни один не дожил до машины Кирюши:

| # | Баг | Чем был страшен | Кто поймал |
|---|---|---|---|
| 1 | `(uint)config.closeHotkey`: `KeyCode.Q` = **113** (Unity: ASCII строчных), а **`VK_Q` = 81** (Windows: ASCII заглавных) | `RegisterHotKey` молча зарегистрировал бы НЕ ТУ клавишу — пункт 5 (выход из игры) мёртв, и click-through вместе с ним | таблица истины + модель конвертера (`TestGlobalHotkeys`) |
| 2 | `SavePositionNow` (Debug.Log + диск) вызывался прямо из `WndProc` на `WM_EXITSIZEMOVE` | нарушение собственного правила оконной процедуры (урок 0.6.5: чужой такт) | `guard_wndproc_discipline` |
| 3 | `Nudge` двигал окно, но не сохранял позицию (`MoveWindowTo(clamped, false)`) — при докстринге «и запомнить позицию» | перемещение стрелками терялось бы при перезапуске — пункт 4 нарушен наполовину | `guard_nudge` + контрольный выстрел |
| 4 | `Revert()` (F8) снимал `WS_EX_LAYERED|WS_EX_TOPMOST`, но не `WS_EX_TRANSPARENT` | окно на вид обычное, но некликабельное — мини-призрак | `guard_no_ghost_on_exit_paths` |
| 5 | `RegisterGlobalHotkeys` при повторном Apply (F7/F8) логировал «выключены конфигом», хотя хоткеи зарегистрированы | враньё в Player.log во время замера — прибор, которому нельзя верить | гвард порядка проверок |
| 6 | `allowClickThrough = ❌` блокировал только глобальный F11, а `Input.GetKeyDown(F11)` в фокусе конфиг обходил | «запретить» означало «наполовину запретить» | `guard_ghost_safety` (воронка) |

Отдельно: класс ошибок №1 из ADR-025 снова в деле — **ни один из шести багов не виден ни
чекеру (типов не знает), ни Editor (player-only ветка вырезана)**. Лечатся только
таблицами истины и контрольными выстрелами в песочнице.

## 2. Что сделано

### 2.1 Драг за любую точку (пункт 1)

Подкласс оконной процедуры (`GetWindowPointer`/`SetWindowPointer` с ветвлением по
`IntPtr.Size` — в 32-битной user32.dll `GetWindowLongPtr` **нет вовсе**). На
`WM_NCHITTEST`, пока держат **Ctrl+Alt** (`GetAsyncKeyState(0x11/0x12) & 0x8000` —
спрашиваем у системы: фокуса может не быть), возвращаем `HTCAPTION = 2`: тащит сама
Windows, со своей инерцией и snap'ом к краям. `HTTRANSPARENT`/`HTNOWHERE` не
перехватываются. Конец перетаскивания — `WM_EXITSIZEMOVE` → флаг `_saveRequested` →
сохранение позиции в кадре Unity (`DrainDeferredSave`): из оконной процедуры нельзя
ни Unity API, ни диск. Делегат держится в поле (собранный GC делегат = падение
процесса), в `OnDestroy` прежняя процедура возвращается.

### 2.2 Шаг стрелками (пункт 2)

`Nudge`: шаг `Mathf.Max(1, config.windowMoveStep)` (дефолт **32 px**), чистая функция
`WindowStateStore.MoveBy` (размер не меняется — гвард идемпотентности `Reposition` не
дёргается), кламп `ClampToScreen` (≥ **48 px** окна на экране: невидимое окно нельзя ни
перетащить, ни нажать), сохранение позиции. В фокусе — опрос Input с Ctrl+Alt;
глобально — только если `globalArrowHotkeys = ✅` (**дефолт ❌**, урок ADR-006:
глобальный хоткей забирает сочетание у всей системы — в игре стрелки до неё не дойдут).

### 2.3 Углы дока (пункт 3)

`DockCorner` enum: порядок значений и есть порядок цикла F10 — **BottomRight = 0,
BottomLeft = 1, TopRight = 2, TopLeft = 3**. `NextCorner` замкнут (TL → BR), мусорный
угол → BR. F9 = `DockTo(BottomRight)` как был (и остался аварийным выходом), F10 =
`DockTo(NextCorner(_corner))`, каждый угол логируется и сохраняется. Геометрия —
чистая функция `DockRect(corner, screenW, screenH, w, h, margin)`; рабочая область —
с монитора окна (`MonitorFromWindow` + `GetMonitorInfo`, `rcWork`) в **абсолютных**
координатах: на втором мониторе слева x отрицательный, «просто сложить» нельзя.

### 2.4 Персист (пункт 4)

Новый файл **`WindowStateStore.cs`** — без единого P/Invoke (чистые функции судит
песочница, Win32 судит F7 — правило ADR-025). `data/window_state.json`, схема
version=1, числа в **инвариантной культуре** (русская локаль: запятая вместо точки
сломала бы разбор), без BOM. Путь: `windowStatePath` из конфига, иначе
`Application.persistentDataPath/data/window_state.json` (можно держать рядом с
сервером). Сохранение — **в момент перемещения** (драг/стрелки/F9/F10), а не на
выходе: аварийное завершение потеряло бы позицию ровно тогда, когда она нужнее.
Чтение — один раз на старте: битый файл/чужая версия/нет позиции → `null` → старт с
`initialDockCorner` из конфига. Приоритет файла над `dockBottomRight` — до первого
F9/F10 в сессии (`_dockPressedThisSession`), позиция из файла прогоняется через
`ClampToScreen` (монитор мог стать другим). `dockBottomRight = ❌` ведёт себя как в
0.6.6: окно остаётся где стоит.

### 2.5 Глобальные хоткеи (пункт 5)

`RegisterHotKey` на «ядро» (Ctrl+Alt+Q, F9, F10) и «дополнения» (F11, опционально
стрелки) — занятое дополнение не отнимает у хозяина выход. `KeyCode` → VK через
конвертер `VirtualKeyOf` (см. баг №1: буквы −32, F-ряд через `VK_F1 = 0x70`, цифры
совпадают). `WM_HOTKEY` **только складывает действие в очередь** — выполняет
`DrainGlobalHotkeys` в `Update` (главный поток, кадр Unity, предел 16 за кадр);
Quit — ровно один `Application.Quit()` в `RequestQuit()`. Дедупликация 0.4 с: окно в
фокусе не исполняет то, что уже исполнено глобально (иначе F11 щёлкал бы туда-сюда).
Честный лог каждой неудачи с `GetLastError`. `OnDestroy`: `UnregisterHotKey` всем
списком + снятие подкласса.

### 2.6 Click-through (пункт 6 — критично)

F11 → `WS_EX_TRANSPARENT` **в паре с `WS_EX_LAYERED`** (без layered мышь не
пропускается). **Двойной предохранитель** в единственной воронке `ApplyClickThrough`:

```
включится ⇔ want
          ∧ config.allowClickThrough          (конфиг не запрещает — ни глобально, ни в фокусе)
          ∧ _globalHotkeysOk                  (ядро хоткеев живо: окно есть чем закрыть)
          ∧ _clickThroughAvailable            (F11 доехал до RegisterHotKey: есть чем выключить)
```

Отказ логируется честно («иначе окно стало бы неубиваемым призраком»). В
`window_state.json` click-through **не пишется никогда**: каждый запуск начинается
кликабельным. Все пути прочь снимают сквозной режим первыми: `RequestQuit` — до
`Application.Quit()`, `Revert` (F8) — вместе с флагом. Win32 только по изменению
состояния (правило 0.6.6). F7 (смена режима) click-through переживает: `ApplyStyles`
сбрасывает `WS_EX_TRANSPARENT` и возвращает по флагу.

### 2.7 Оверлей и клиент

Строка 7 оверлея: `окно: угол BottomRight (из файла) · click-through выкл · глоб.
хоткеи да` (`Describe()` работает и в Editor — поля состояния объявлены вне `#if`).
Клиент находит компонент `GetComponent<TransparentWindow>()` и не порождает его сам.
Высота прямоугольника оверлея — 192 (гвард 0.6.6 обновлён структурным правилом).

- [ ] **F11** — клики проходят СКВОЗЬ окно в игру (курсор в углу не трогает модельку);
      F11 ещё раз — окно снова ловит клики;
- [ ] гвард призрака: если хоткеи заняты другой программой (в логе `RegisterHotKey не
      удался`), F11 обязан ответить `click-through ОТКЛОНЁН` — и окно остаётся
      кликабельным и закрываемым;
- [ ] перезапуск после click-through ВКЛ — окно стартует **кликабельным** (флаг не
      персистится);
- [ ] F7 по режимам со включённым click-through — сквозной режим переживает смену
      стекла; F8 — снимает всё (окно снова кликабельно);
- [ ] строка 7 оверлея показывает угол/click-through/хоткеи и не дрожит.

### 5.5 Если хоткей занят

`RegisterHotKey не удался: … GetLastError=1409` — сочетание держит другая программа
(частые виновники: скриншотеры, оверлеи). Незанятое ядро важнее всего: без
Ctrl+Alt+Q click-through не включится вовсе — это не баг, это предохранитель.

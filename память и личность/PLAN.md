## 1. РОЛЬ

Я — ведущий разработчик и архитектор проекта **LILITH-CORE**: домашний Python-стек
ИИ-компаньона (оркестратор, память, уши, горло, лицо, руки, мосты).

**Целевая машина:** Windows 11, RTX 3060 12GB, i7-12700KF, 32GB RAM.
**Песочница строителя:** БЕЗ GPU, без Unity и без локальных моделей → слой «мозг»
сделан интерфейсом (OpenAI-совместимый клиент: `base_url` / `model` / `api_key`
из конфига) + mock для тестов; лицо проверяется pytest-гвардами, эмулятором
`unity_face_probe.py` и чекером C#-синтаксиса. Модели в песочнице НЕ скачиваются.

**Точка правды F7:** реальная сборка у Кирюши (Windows, Unity **6000.0.84f1**,
UniVRM **0.131.2**, Built-in RP, VRM 1.0). Песочница — доказательство логики,
F7 — доказательство реальности. Расхождение между ними решается в пользу F7.

## 2. РЕГЛАМЕНТ РАБОТЫ (циклами)

Цикл этапа N:
1. реализовать модули этапа;
2. написать и прогнать pytest в песочнице, чинить до зелёного;
3. обновить README (запуск на Windows: venv, конфиг, старт) и доки клиента;
4. отправить Кирюше результат: отчёт (что сделано / как запустить / что проверить
   руками) + архив проекта артефактом.

**Хотфикс** (вне цикла этапа) = отчёт `🔧 ОТЧЁТ ПО v0.X.Y` + `RELEASE_0.X.Y.md` в репо
+ артефакт-zip. Объём правки **минимальный**: серверный Python не трогается, если баг
клиентский (и наоборот). Каждое решение, которое меняет контракт или поведение по
существу, — в `docs/DECISIONS.md` как ADR.

**На этап N+1 переходить ТОЛЬКО после команды Кирюши «дальше».**

Миграция Unity у Кирюши: копируется **ТОЛЬКО** `unity-client/Assets/LilithFace/Scripts/`;
его `.asmdef` НЕ затирается (там ручные ссылки UniGLTF, UniHumanoid, VRM10, UniGLTF.Utils).

## 3. СТИЛЬ

Python 3.11 · тайпхинты · докстринги на русском · loguru везде · C# для Unity без
внешних зависимостей (ADR-016: только stdlib + UniVRM, всё VRM-специфичное под
`#if LILITH_UNIVRM`) · гварды и регрессионные тесты на каждое найденное место ·
контрольные выстрелы по своим же чекерам («чекер не всегда зелёный»).

## 5. ЧТО УЖЕ ЗАЛОЖЕНО ПОД БУДУЩИЕ ЭТАПЫ (чтобы не переделывать)

* **`config/config.yaml`** содержит секции всех девяти этапов (`brain`, `memory`, `voice`,
  `face`, `hands`, `bridges`, `stream`, `features`, `logging`) — формат конфига не меняется.
* **`pyproject.toml`** — extras по этапам: `[brain] [memory] [voice] [face] [hands] [bridges] [stream]`.
* **Контракт обработчика реплик**: `ReplyHandler`, фабрика `build_reply_handler(settings)` —
  мозг встал на место эха одной строкой, шину и панель не переписывали.
* **Протокол шины** (`protocol.py`) включает `state` и `error` — на них лягут баннеры
  подтверждения (этап 7) и отчёты инструментов. `SessionManager.broadcast()` готов.
* **Веб-панель**: баннер подтверждения с 25-с отсчётом нарисован (`showConfirm`), ждёт
  `state.confirm` от сервера → этап 7.
* **Память персон (6.5)**: колонка `messages.persona_id` + идемпотентная миграция,
  `Journal.add_message(persona_id=…)`, `MemoryCore.remember_turn(persona_id=…)`,
  `memory_scope` в карточке персоны — интерфейс готов (ADR-018), осталось хранилище.
* **Руки (7)**: `hands.confirm_timeout_sec = 25.0` в конфиге, спека
  `docs/STAGE7_HANDS_SPEC.md` (US1–USn, sandbox только директорией).
* **Лицо**: `face/vtuber_bridge.py` и VMC-слот помечены **legacy** (ADR-021 Q4),
  в этап 7 не входят, оба флага в поставке `false`.
* **Unity-клиент**: все настройки — поля инспектора (`LilithClientConfig`), код при
  переезде не правится; `FaceRig` — единственное место с VRM-кодом (под `#if LILITH_UNIVRM`).
